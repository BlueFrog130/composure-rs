# Changelog

Every published crate (`composure`, `composure_macros`, `composure_commands`, `composure_sync`,
`composure_adapter_cloudflare`, `composure_adapter_tokio`) shares one version, released together.
Entries are generated by [knope](https://knope.tech) from the change files in `.changeset/`.

## 0.1.1 (2026-10-20)

### Fixes

#### Deferred update errors become ephemeral follow-ups; Components V2 conflicts are caught

When `ctx.defer_update(..)` work fails, the error is now sent as an ephemeral follow-up instead of replacing the component's message, which kept failing on Components V2 messages and lost the message's state (#12).

A Components V2 response or deferred edit that also sets `content`, `embeds` or a poll is now a `HandlerError` naming the conflicting field, instead of Discord's bare "This interaction failed" (#13).

## 0.1.0 (2026-10-19)

### Features

#### Commands defined once, as functions

`#[command]`, `#[group]`, `#[autocomplete]` and `#[derive(Choice)]` turn functions into slash and
context-menu Commands: Options from typed parameters, the description from the doc comment, the
response from the return value. `#[app]` collects Commands, handlers, Views and nested Apps, and
rejects duplicate commands, Scope overflows and `custom_id` prefix collisions at compile time.

#### Components, modals and Views

`#[component]` and `#[modal]` handlers routed by `custom_id`, with their state encoded in it;
typed `#[derive(Modal)]` forms; Components V2 messages and modals as `rsx!` markup, and `#[view]`
components with inline handlers. Themes fill in embed colors, branding and container accents.

#### REST, deferring and Webhook Events

An async REST client for every Discord Endpoint, opt-in per resource; Deferred Responses finished
as Background Work; follow-ups and file uploads; Webhook Events on `/events`.

#### Adapters and Sync

`composure_adapter_cloudflare` serves bots on Cloudflare Workers, `composure_adapter_tokio` from a
tokio/hyper server, both through the shared `composure::adapter` pipeline. `composure_sync`
makes Discord's stored commands match the App, with a plan, confirmation and CI drift checks.

#### Documentation

A guide in `composure::guide` covering every feature, with compiled examples and a reference of
every `rsx!` tag and attribute; every public item documented.
