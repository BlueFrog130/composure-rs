# Webhook Events share the Adapter entrypoint, routed by path

Discord's Webhook Events (`APPLICATION_AUTHORIZED`, `ENTITLEMENT_CREATE`, ...) arrive at a separately configured URL with the same Ed25519 signing as Interactions. The Adapter serves both from one entrypoint and routes by path (default `/events`, `with_events_path` to change it) to the handler's `EventHandler` implementation. A Command Set gets one from `commands! { ...; events = MyEvents; }`, or ignores every event without it; other handlers implement the trait directly (every method defaults to ignoring). `handle_event` is exposed for custom routing and host tests. Events are ACKed with 204 immediately and handled as Background Work (the handler is moved into it, so it must be `'static`), since Discord expects the ACK within 3 seconds and retries unacknowledged events; handler errors are therefore only logged. Unknown event types, and data that does not match its model, decode to `Event::Unknown` with the raw JSON instead of failing, so new or changed Discord events never break a deployed bot or get its events URL disabled for repeated failures.
