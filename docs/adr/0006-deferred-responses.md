# Deferred Responses hand Background Work to the Adapter

A Command that needs more than Discord's 3-second window calls `ctx.defer(..)` (or `defer_ephemeral`, `defer_update` for components), passing an async closure that receives a `DeferredCtx`. Dispatch returns the type 5/6 reply plus the `'static` Background Work; the Adapter sends the reply, runs the work after responding (`wait_until` on Cloudflare) and edits the original response with its result, or with the Handler error message on failure. The hot path keeps the borrow-only `Ctx<'a>`; only deferred work pays for owning the Interaction (`Rc`) and State. Ephemerality is chosen at defer time because Discord fixes it on the deferred reply. Background Work is bounded by the platform (about 30s on Workers) even though the interaction token lasts 15 minutes; longer jobs are out of scope. The same mechanism ACKs Webhook Events (0008) and sends initial responses carrying files: the Adapter POSTs the callback endpoint as multipart and answers the original request with 202.
