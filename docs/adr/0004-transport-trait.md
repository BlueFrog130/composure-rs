# REST over an Adapter-provided Transport

The REST client is async and talks to Discord through a `Transport` trait (`send` a request, `sleep` for rate-limit waits) instead of depending on an HTTP client. Workers has no `reqwest`-friendly runtime and no `thread::sleep`, and the deploy-time CLI has no Workers `Fetch`; each side implements `Transport` with what it has (`worker::Fetch` + a JS timer on Cloudflare, a `reqwest` feature for native). Requests and responses are our own minimal types rather than the `http` crate's, keeping core's dependency tree small; core encodes bodies (JSON or multipart) so a Transport only moves bytes. Rate limiting is reactive only: a 429 is waited out via `Transport::sleep` when `retry_after` is under a configurable cap (short at runtime, long for Sync), otherwise returned as `Error::RateLimited`. Isolates share no memory, so per-bucket tracking would be mostly cold; the client leaves room for a pluggable limiter later.
