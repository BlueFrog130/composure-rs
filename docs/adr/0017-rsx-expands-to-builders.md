# `rsx!` expands to builders, as Leptos's `view!` does

Supersedes the IDE part of ADR 0015 (the hidden `tags` module). `rsx!` used to know every tag: a generator per tag assigned the component struct's fields, checked placement itself, and a hidden `composure::command::tags` module (one const per attribute, generated from a table in the macro) gave rust-analyzer something to complete and document. Completion then needed a scan of the raw tokens for rust-analyzer's marker identifier, and the expansions with and without it had to line up byte for byte; the table, the generator and the struct fields could drift apart. Leptos's `view!` keeps its macro thin instead, and `rsx!` now does the same with Discord's components. A built-in tag is its type's `builder()` (`::composure::types::Container`, only the type's name at the tag's span, so hover and go-to-definition reach the type and it highlights as one), each attribute a documented builder method (`.accent_color(..)`, a flag `.primary(true)`, `on:click=..` `.on_click(custom_id)`), each child a `.child(..)` bounded by a trait per parent (`RowChild`, `ContainerChild`, ... with `on_unimplemented` messages, the `IntoView` blankets `do_not_recommend`), and `.build()` at the tag's span returns an `Element<T>` that carries its files and first `custom_id` error up to the View. So rustc checks attribute names (with "a method with a similar name") and placement (text in a `<Row>` is "`&str` cannot go in a `<Row>`", at the text), and rust-analyzer completes, documents and highlights attributes as methods with no help. Each child sits in braces spanned at its tag, because a block's span is its braces and an error about the child must point at it rather than at the whole macro (Leptos allows `unused_braces` for the same braces). A single name that is not a built-in tag resolves through a glob of `command::elements` (every tag's type under its markup name) in a block of its own, so `<Con` completes from the built-in tags and the sub-Views in scope alike, user expressions never see the glob, and built-in names stay reserved as before. User Views take the same protocol: their Props builder, `.children(View)`, `.build()` at the tag (a missing Prop's error points at it). The macro keeps what only it can see: inline handlers, a modal's inputs against its `on:submit` parameters, required attributes and conflicting ones, the counts Discord limits, and locals an inline handler cannot use. Its required-attribute errors are recorded and the tag is still generated, so a tag being typed keeps completing. As in Leptos, errors are collected, deduplicated, capped at 16 and each anchored at the offending token, with tests for that locality, and expansions are snapshot-tested. Leptos retries a failed parse with `/>` appended so a half-typed tag still expands; `rsx!` closes every tag the next one starts inside of (`<Row><Butt</Row>`), not only the last, and still reports the original errors, so markup missing its `/>` never compiles. Rejected: keeping the tags module and the marker scan (two sources of truth and an offset invariant to protect); typestate builders for required attributes (worse messages than the macro's, for little gain); keeping the macro's placement checks next to the trait bounds (the same rules twice).
