# REST client and endpoints live in core, behind features

The REST client (`InteractionClient`, `BotClient`), its errors and every endpoint live in `composure::rest`, gated per resource (`rest-messages`, `rest-guilds`, ...) with `rest` / `tier1` / `full` aliases, and `composure_api` is removed. Core stays free of any HTTP *implementation* (see 0004), but owns the endpoints so `Ctx` and `DeferredCtx` can expose first-class methods (`ctx.followup(..)`, `ctx.bot()`) and the Adapter can finish Deferred Responses without a second crate. With endpoints in a separate crate, inherent methods on core's clients would be impossible and every resource would need an extension trait. Endpoints are hand-written, take borrowed body structs and return a lazily-decoded `Response<T>`; a vendored, pinned copy of Discord's OpenAPI spec checks the route table in tests and reports what is not yet implemented. Bundle size is controlled by features and LTO, as with Command Definitions (0003).
