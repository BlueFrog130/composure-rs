# Credentials and Bot Data are typed values in core; loading happens at the edge

Bots load configuration in very different ways: Workers read secrets and vars from `Env` (only per request, and not iterable), a hosted server may use the `config` crate, `figment`, `envy`, or plain `std::env`. Like serenity, twilight, axum and sqlx, core never loads configuration itself; it defines what it needs as typed values and every loader produces them through serde. `Credentials` (`public_key` as hex, checked at deserialize; optional `bot_token`, with a `token` alias so `envy::prefixed("DISCORD_")` matches `DISCORD_TOKEN`, and a redacting `Debug`; optional `application_id`, a string or an integer) derives `Deserialize`, so `cfg.get::<Credentials>("discord")` works without Composure depending on any loader. The conventional names (`DISCORD_PUBLIC_KEY`, ...) stay in core behind `Credentials::from_lookup(|name| ..)`, which both Adapters wrap (`std::env` on tokio, `Env::var`, which reads secrets too, on Workers), with one `CredentialsError`. Parsing the `PublicKey` stays in the Adapter, since web-crypto's import is async and cached per isolate. The tokio Adapter takes `new(Credentials)` (`from_env()` is sugar). The Cloudflare Adapter takes async closures, `with_credentials(async |env| ..)` and `with_data(async |env| ..)`, because `Env` only exists per request and some sources (the Secrets Store, KV) are async: they run once per isolate and are cached (a failure answers 500 and is retried). The bot's own configuration, Bot Data, reaches Commands the same way on both: a core `HasData` trait (`type Data`) implemented by `Host<T>` and `Worker<T>`, so a platform-agnostic Command takes `Ctx<impl HasData<Data = MyConfig>>` instead of looking up strings through a `Vars` trait; when a platform's Bot Data holds more (tokio's server state), the Command bounds `Data: AsRef<MyConfig>` and the bot implements `AsRef`, which the orphan rule allows from the crate owning the Bot Data type (a generic `HasData<T>` would need `impl HasData<MyConfig> for Host<Server>`, impossible when neither type is local). Bot Data is `Send + Sync` (ADR 0012), so Workers bindings stay on `Env`. `Platform` keeps only `bot_token()`. Sync keeps its own `SyncConfig` (it needs no public key; an optional one would weaken `Credentials` everywhere else). The alternatives were builder methods per Adapter only (no single type for serde loaders, each Adapter re-parses), and a loader in core behind features (ties core to one config crate and to `std::env`, which Workers lack).
